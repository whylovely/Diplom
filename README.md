# 💰 Система учёта личных финансов

Кроссплатформенное клиент-серверное приложение для управления личными финансами, разработанное в рамках выпускной квалификационной работы.

Приложение позволяет вести личный бюджет, управлять банковскими и виртуальными счетами, учитывать доходы, расходы, переводы и обязательства, анализировать финансовую информацию, получать актуальные курсы валют и синхронизировать данные между локальным клиентом и сервером.

# 📖 О проекте

**Система учёта личных финансов** предназначена для централизованного управления личными финансовыми данными.

Основная идея приложения заключается в сочетании локального клиента и серверной части:

* клиент обеспечивает удобный пользовательский интерфейс;
* локальная база данных позволяет работать с данными без постоянного подключения к Интернету;
* сервер предоставляет REST API;
* PostgreSQL используется для централизованного хранения данных;
* механизм синхронизации позволяет обмениваться изменениями между клиентом и сервером.

Система рассчитана на работу с несколькими счетами и валютами, поддерживает доходы, расходы, переводы, обязательства, категории и финансовую аналитику.

---

# ✨ Основные возможности

## 💳 Управление счетами

Пользователь может:

* создавать счета;
* редактировать существующие счета;
* удалять счета;
* задавать валюту счёта;
* просматривать текущий баланс;
* работать одновременно с несколькими счетами;
* использовать счета в разных валютах.

Поддержка мультивалютности позволяет использовать приложение для учёта денежных средств независимо от валюты хранения.

---

## 🏷️ Категории

Система поддерживает категории финансовых операций.

Возможности:

* создание собственных категорий;
* редактирование категорий;
* удаление категорий;
* разделение доходов и расходов;
* группировка операций;
* анализ расходов по категориям.

Категории используются как для ручного учёта операций, так и для последующего формирования отчётов.

---

## 💵 Финансовые операции

Приложение поддерживает основные типы финансовых операций:

* **доходы**;
* **расходы**;
* **переводы между счетами**.

Для финансовых операций используется принцип двойной записи.

Например, перевод денежных средств между двумя счетами одновременно изменяет состояние обоих счетов:

```text
Счёт A
   │
   │ -1000 ₽
   ▼
Счёт B
   │
   │ +1000 ₽
   ▼
```

Это позволяет сохранять согласованность финансовых данных.

---

## 📅 Календарь операций

Операции могут быть привязаны к определённой дате.

Календарное представление позволяет:

* просматривать операции за конкретный день;
* анализировать операции за период;
* отслеживать историю расходов;
* находить запланированные операции.

---

## 🔄 Шаблоны операций

Для часто повторяющихся финансовых операций предусмотрены шаблоны.

Например:

```text
Зарплата
↓
Доход
↓
Счёт "Основной"
↓
1 раз в месяц
```

Шаблоны позволяют сократить количество ручных действий при регулярном учёте финансов.

---

## 📋 Обязательства

Система позволяет вести учёт финансовых обязательств:

* долгов;
* кредитов;
* платежей;
* сроков исполнения;
* просроченных обязательств.

Пользователь может контролировать текущие обязательства и отслеживать приближение сроков платежей.

# 📊 Финансовая аналитика

Приложение предоставляет инструменты анализа финансовой информации.

Доступны:

* динамика доходов;
* динамика расходов;
* расходы по категориям;
* обороты счетов;
* изменение баланса;

Для построения графиков используется **LiveCharts2**.

```text
        │
        ▼

        │
        ▼

        │
        ▼

        │
        ▼
    Диаграммы
```

# 💱 Валютные курсы

Приложение позволяет получать актуальную информацию о курсах валют.

Используются внешние источники:

* **Центральный банк Российской Федерации** — для фиатных валют;
* **CoinGecko** — для криптовалют.

# 🔐 Аутентификация и безопасность

Серверная часть использует JWT-аутентификацию.

Поддерживаются:

* регистрация пользователей;
* авторизация;
* JWT access-токены;
* refresh-токены;
* роли пользователей;
* административные права;
* блокировка пользователей.

Предусмотрены две основные роли:

```text
User
Admin
```

### User

Обычный пользователь системы.

Имеет доступ к собственным:

* счетам;
* категориям;
* операциям;
* обязательствам;
* отчётам.

### Admin

Администратор имеет дополнительные возможности управления системой:

* просмотр пользователей;
* блокировка аккаунтов;
* управление пользователями;
* доступ к административной панели.

# 🚀 Быстрый запуск

Самый простой способ запустить сервер и PostgreSQL — использовать Docker Compose.

### 1. Клонирование репозитория

```bash
git clone https://github.com/whylovely/Diplom.git
cd Diplom
```

### 2. Запуск контейнеров

```bash
docker compose up --build
```

После завершения сборки будут запущены:

```text
PostgreSQL
   │
   └── finance_pg

ASP.NET Core
   │
   └── finance_server
```

### 3. Проверка сервера

Swagger API:

```text
http://localhost:5273/swagger
```

Административная панель:

```text
http://localhost:5273/admin
```

# 🐳 Запуск через Docker

В проекте используется два основных контейнера:

```text
┌─────────────────────────────┐
│        finance_server       │
│        ASP.NET Core 8       │
│           :8080             │
└──────────────┬──────────────┘
               │
               │
┌──────────────▼──────────────┐
│          finance_pg         │
│        PostgreSQL 16        │
│           :5432             │
└─────────────────────────────┘
```

Docker Compose автоматически создаёт PostgreSQL и запускает сервер после успешной проверки готовности базы данных.

Для PostgreSQL используется healthcheck:

```yaml
healthcheck:
  test: ["CMD-SHELL", "pg_isready -U finance_user -d finance"]
```

Сервер запускается только после того, как база данных становится доступной.

# 🔑 Аутентификация

Типовой процесс авторизации:

```text
Регистрация
     │
     ▼
Авторизация
     │
     ▼
Access Token
     │
     ├──────────────► API
     │
     ▼
Refresh Token
     │
     ▼
Обновление Access Token
```

JWT access-токен используется для доступа к защищённым API-методам.

Refresh-токен позволяет получить новый access-токен без повторного ввода учётных данных.

# 💰 Работа с финансовыми операциями

Основными сущностями системы являются:

```text
User
 │
 ├── Accounts
 │      │
 │      └── Transactions
 │
 ├── Categories
 │
 ├── Obligations
 │
 └── Reports
```

Операция может быть:

### Доходом

```text
Источник дохода
       │
       ▼
   + Счёт
```

### Расходом

```text
   Счёт
     │
     ▼
  - Расход
```

### Переводом

```text
Счёт A ────── -X ──────►
                          │
                          ▼
                      Счёт B
                          ▲
                          │
                         +X
```

Такой подход позволяет корректно учитывать изменения баланса.

# 🔄 Синхронизация

Одной из особенностей приложения является возможность локальной работы.

Клиент хранит данные в:

```text
SQLite
```

Сервер использует:

```text
PostgreSQL
```

Обмен данными происходит через REST API.

Общая схема:

```text
             Client
                │
          ┌─────▼─────┐
          │   SQLite  │
          └─────┬─────┘
                │
                │ Sync
                ▼
          ┌────────────┐
          │ REST API   │
          └─────┬──────┘
                │
                ▼
          ┌────────────┐
          │ PostgreSQL │
          └────────────┘
```

Поддерживается двусторонняя синхронизация.

При обновлении данных система должна учитывать возможные конфликты между локальной и серверной версиями.

Сервер использует Entity Framework Core Migrations.

```bash

    --project Server \
    --startup-project Server
```

Применение миграций:

```bash
dotnet ef database update \
    --project Server \
    --startup-project Server
```

> ⚠️ Эти учётные данные предназначены только для локальной демонстрации. В production-окружении их необходимо изменить или удалить.

# 📦 Развёртывание

Серверная часть подготовлена для контейнеризированного запуска.

Образ строится в несколько этапов:

```text
.NET SDK 8
     │
     ▼
dotnet restore
     │
     ▼
dotnet publish
     │
     ▼
ASP.NET Runtime 8
     │
     ▼
Server.dll
```

Использование multi-stage Docker build позволяет не включать полный SDK в конечный runtime-образ.

Контейнер сервера слушает порт:

```text
8080
```

На локальной машине он доступен через:

```text
5273
```

# 🌍 Production

Перед развёртыванием в production необходимо изменить как минимум:

* JWT secret;
* пароль PostgreSQL;
* параметры подключения к БД;
* настройки CORS;
* настройки HTTPS;
* тестовые учётные записи;
* параметры внешних API;
* переменные окружения.

Не рекомендуется хранить production-секреты непосредственно в:

```text
docker-compose.yml
```

или исходном коде.

Для production следует использовать секреты и переменные окружения платформы развёртывания.

# 🔒 Безопасность

При использовании проекта необходимо соблюдать следующие рекомендации:

1. Не использовать демонстрационный JWT secret в production.
2. Не использовать стандартный пароль PostgreSQL в production.
3. Не публиковать `.env` с секретами в Git.
4. Использовать HTTPS.
5. Ограничить доступ к PostgreSQL.
6. Использовать отдельную production-базу данных.
7. Регулярно обновлять зависимости.
8. Не использовать демонстрационные аккаунты в реальной эксплуатации.

Проект логически разделён на несколько функциональных областей.

| -------------- | ------------------------- |
